# Love & Rope Studio Website

This is a lightweight Astro website for Love & Rope Studio, a shibari teacher offering group classes and private sessions.

Live site:

```text
https://keyvaann.github.io/rope/
```

## Requirements

- Node.js `22`, managed with `.nvmrc`
- npm
- GitHub Pages configured to deploy with GitHub Actions
- Pages CMS access for browser-based content editing

## Fresh Start

Clone the repo, install dependencies, and run the site locally:

```bash
git clone git@github.com:keyvaann/rope.git
cd rope
nvm use
npm ci
npm run dev
```

Run the full quality check before pushing changes:

```bash
npm run check
```

`npm run check` runs Astro type checks and builds the static site.

## Editing The Website

The easiest way to update the website is with Pages CMS.

Pages CMS is configured in:

```text
.pages.yml
```

1. Go to `https://app.pagescms.org`
2. Sign in with GitHub
3. Open the `keyvaann/rope` website
4. Choose the section you want to edit
5. Make your changes
6. Save

After saving, GitHub will automatically publish the updated website. This usually takes a minute or two.

## Editing Sections

Pages CMS is split into simple sections:

- `Site Settings`: studio name, tagline, footer tagline, teacher name, email, location, footer links, and social links
- `Home Page`: homepage headline, introduction, feature cards, and homepage images
- `About Page`: teacher bio, teaching philosophy, experience text, and about page image
- `Classes Page`: class descriptions, what to bring, class details, safety expectations, class FAQ, and images
- `Private Sessions Page`: private session text, topics, what is not offered, practical details, clothing guidance, pricing, safety, booking flow, cancellation note, FAQ, and images
- `Contact Page`: contact text, inquiry checklist, privacy note, location, social section, and contact image

## Content Files


## Images

The site includes starter images. You can replace them with your own photos in Pages CMS.

Current starter images and licenses are listed in `IMAGE_CREDITS.md`.

Image files live in:

```text
public/images/
```

Images in `public/images` are served from `/rope/images/...` on GitHub Pages.

When adding or replacing images:

- Add clear alt text describing the image for someone who cannot see it
- Add image width and height in Pages CMS when known
- Strip EXIF/GPS metadata before committing public images
- Update `IMAGE_CREDITS.md` when using third-party or credited images
- Keep imagery safe, craft-focused, and aligned with the site tone

Recommended image sizes:

- Hero images: `2400 x 1600`
- About page image or teacher portrait: `1200 x 1500`
- Class and session cards: `1600 x 1200`
- Detail images: `1600 x 1000`

## SEO And Sharing

Page metadata is handled in:

```text
src/layouts/BaseLayout.astro
```

The layout outputs:

- page title
- meta description
- canonical URL
- Open Graph metadata
- Twitter card metadata
- favicon link

The sitemap is generated by `@astrojs/sitemap` during build. Do not edit `dist/sitemap-*.xml` manually.

The source robots file is:

```text
public/robots.txt
```

It points search engines to:

```text
https://keyvaann.github.io/rope/sitemap-index.xml
```

The favicon source is:

```text
public/favicon.svg
```

## Deployment

GitHub Pages deployment is handled by:

```text
.github/workflows/deploy.yml
```

Deployment flow:

1. Push to `main`
2. GitHub Actions runs `npm ci`
3. GitHub Actions runs `npm run check`
4. Astro builds the static site into `dist/`
5. GitHub Pages publishes `dist/`

Important deployment assumptions:

- The repository is `keyvaann/rope`
- Astro `site` is `https://keyvaann.github.io`
- Astro `base` is `/rope`
- GitHub Pages must be set to use GitHub Actions, not branch-based publishing

## Project Decisions

- Astro is used because the site is static, simple, and fast.
- Pages CMS is used so content can be edited without touching code.
- Content is split into small JSON files so each page has its own editor section.
- GitHub Pages is used for free static hosting.
- The site intentionally keeps placeholder-friendly content until final business details are ready.

## Before Launch Checklist

Before sharing the site publicly, update this starter content:

- Studio name
- Teacher name and bio
- Email address or booking method
- Location or service area
- Social links
- Class descriptions
- Private session descriptions
- Pricing or rate language
- Cancellation policy
- Images and image descriptions

Before pushing launch changes:

```bash
npm run check
```

After deployment, verify:

- The live homepage loads at `https://keyvaann.github.io/rope/`
- Navigation links work
- Images load from `/rope/images/...`
- `robots.txt` points to `sitemap-index.xml`
- Contact details are correct
